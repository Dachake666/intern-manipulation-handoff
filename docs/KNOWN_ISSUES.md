## 运动与复现

| 问题 | 影响 | 维护要求 |
|---|---|---|
| Track C 双次抓放与瓶子五轮完整日志不足 | 历史说明不能授予完整源码/运行组合资格 | 保持 LIMITED；补原日志与身份，不能用其他轨迹日志替代 |
| MPC / VAJ3 核心历史哈希缺失 | wrapper、base、报告存在也不能确定旧算法字节 | `restore_run.py` 保留未绑定项；新增实验记录所有动态依赖 SHA |
| 部分 field wrapper 失败时删除/不写 JSON | 成功报告不能覆盖异常路径 | 保留终端日志；修复需新版本、异常路径回归与独立现场验证 |
| 旧执行器的软停、迟到和收尾策略不同 | 同名依赖合并可能改变控制行为 | 保持逐轮组合；共享重构先有回归，再独立资格检查 |
| 双臂碰撞资格 REJECT | 动画和只读限位报告不是执行资格 | 补可信开/闭夹爪几何、右臂真实限位/TCP、场景和 SDK 并发语义 |
| 冻结 Track C 缺完整 GUI 专用入口 | `verify_left_track_c.py` 仅核对点流，任务生成器会重新规划 | 新增加载冻结轨迹的全程回放并绑定 SHA，再做人工检查 |
| 历史文档与文件名含 REALVERIFIED | 名称可能强于证据 | 以当前版本表、运行报告和 SHA 绑定为准，不改历史字节掩盖差异 |
| 旧子目录校验表含陈旧值或历史路径 | 不能用子目录清单校验当前精简布局 | 使用根清单；具体差异见来源映射和历史完整性记录 |

Track A 的五份最终成功记录仅证明对应固定现场及精确文件组合。Servo/MPC 完成记录不能替代完整碰撞、持物、放置和动态资格。D2 早期 MPC 与 D3 部分缺陷只有证据，不能承诺用现有源码重现故障。

## 视觉与标定

1. C++ 手眼 `camera_calibration.cpp` 在残差超限设置错误后仍写矩阵，并可能重置 error=0。必须让失败停止写入/激活，并增加回归；服务 success 不等于标定合格。
2. `src/frame_calibration/analysis/fit_eye_to_hand.py` 固定输出 VALIDATED/locked，缺独立质量批准门；末五个验证样本未执行同等同步检查。需覆盖所有样本同步、残差阈值和现场静止条件。
3. 手眼会话切换/提前返回未完整隔离样本。需明确内存与磁盘清理、时间同步、单位、末端角色、四元数顺序和矩阵方向；服务输出是 4×4 共16个数。
4. 39 组手眼样本属于四个编号组，不能直接合并为同批合格数据。旧高残差结果及 test1/multiple 不同矩阵均不能自动激活。
5. C++ ROS 服务/动作与 `vision_observation.v1`、`robot_mission` 尚未完成适配。OBJECT_POSE/GRASP_POSE/EE_POSE、米/毫米和一次 TCP 补偿必须明确。完整视觉自主抓放尚未验收。
6. `calib_common.py` 保留重建与待核标记；历史参考/最新文件名不代表当前有效标定。腰、底盘、工具、相机或工位变化后重新核查。

## 环境与设备

- 仿真已在参考平台的独立虚拟环境完成安装和选定回归；厂商 SDK、ROS/C++ 与格式化后的操作系统部署仍需单独验收。SDK wheel 仅支持 CPython 3.10 / Linux x86_64。
- 检测代码包含 SAM3 ZeroMQ client，匹配的服务端、模型和启动环境未在默认包中。仅有 ONNX 模型不能构成完整检测服务。
- 厂商库架构、SONAME/ABI、Orbbec 版本差异及 `vision_lib` 声明仍需核对。主 launch 不启动手眼节点；构建和启动应分别验收。
- 网络地址和设备身份为运行时配置，当前现场状态须重新确认。能够连通不代表机器人身份已核实。
- 视觉包部分许可证字段为 TODO；不得补写没有来源依据的授权声明。

历史原说明可从 `PRE_PRUNE` 或对应成果节点读取；操作入口使用当前文档。验证范围和实际执行命令见 `verification.json`，新增验证按 [MAINTENANCE](MAINTENANCE.md) 登记。
