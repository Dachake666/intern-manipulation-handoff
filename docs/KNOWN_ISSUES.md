本次整理不顺手修复收到源码，不把收到的当前代码说成缺失。后续修复进入独立开发提交，冻结源码/轨迹/日志保持原字节与来源映射。

## 使用有效视觉坐标前必须解决

1. **Debian 手眼残差拒绝逻辑被覆盖。** `deps/vision/vision_hand_eye/src/camera_calibration.cpp` 在旋转均差 >10 或平移均差 >100 时设置 -105，仍写入矩阵，之后重置 error 为 0，服务可能返回 success=true。需要让失败停止写入/激活，并补回归检查；不能凭 success 判定有效标定。
2. **Mac 手眼工具缺质量批准门。** `fit_eye_to_hand.py` 固定输出 VALIDATED 和 locked=True；末 5 个验证样本没有同样的同步检查，schema 也不限制残差上界。矩阵可计算、契约可解析不等于标定有效。需要独立质量阈值、所有样本同步与现场静止条件证据。
3. **手眼会话与坐标角色尚未闭合。** C++ request_type=1 配对当前图像与提交的手位姿；2 求解内存样本但若干提前返回不清理；3 只移除最后一个内存配对，不删磁盘样本；改变 workspace_id 不隔离/清空旧样本。建立显式会话与清理规则，并确认单位、时间同步、末端/工具角色、四元数 xyzw 与矩阵方向。服务实际输出 4×4 的 16 个数，README 的 12 个数说明不适用。
4. **没有新的合格外参。** 39 组样本是四个编号组，不能直接当同批合格采集。归档矩阵仍对应 8/26 旧高残差结果；源码 test1 与 multiple 的矩阵又不同，实际运行配置未知。本轮没有重新拟合，不能自动覆盖权威标定或使能视觉运动。
5. **接口适配未完成。** C++ ROS vision_interface 服务/动作与 Mac `vision_observation.v1`/robot_mission 不可直接互换；视觉米与 SDK 毫米、OBJECT_POSE/GRASP_POSE/EE_POSE、TCP 一次补偿和变换来源要在适配层明确。视觉抓放闭环仍未验收。

7. **SAM3 服务端未识别。** C++ 检测初始化调用 ZeroMQ client，示例 localhost:5555；收到源码只识别到 client。服务端启动、模型、协议对应版本尚未闭合，完整检测服务不能仅凭 ONNX 文件认定可复现。
