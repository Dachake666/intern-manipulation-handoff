# SDK 8080监听与使能状态排查

用途：SDK 初始化后 link 正常，却读到 enable/servo 为 false，且状态回传不稳定时，先检查控制程序与监听端口归属。历史案例中，暂停但未退出的 SDK 进程仍占用 8080，干扰状态初始化；这一现象不能作为所有使能异常的唯一原因。

## 只读检查

以下命令在实际运行 SDK 的系统/容器执行：

```bash
ss -ltnp 'sport = :8080'
ps -eo pid,ppid,stat,lstart,args
```

核对监听 PID、进程启动时间、状态、所属任务和容器。`STAT=T` 表示暂停，进程与端口可能仍存在；Ctrl+Z 不等于退出。当前操作者应先确认机器人运动已停止、对象状态安全及保护/速度已恢复，再按正常退出流程处理确认不再需要的进程。不要按端口批量杀进程，不要并行启动另一个控制器争抢会话。

## 继续排查

- 核对真实机器人/本地 IP、ARM ID、SDK wheel 身份、运行参数和机器人锁。
- 对比初始化、状态回传、enable/servo读取和错误码的时间顺序，不只截取最终布尔值。
- 状态问题未定位前，不通过增加固定 sleep、绕过使能检查或放宽限位强行继续运动。
- 保留完整失败终端日志，先脱敏副本，再登记执行器与 SDK 依赖 SHA。

端口问题消失、使能状态稳定和抓放成功是三个不同结果。本说明不证明瓶子五轮抓放的完整运行证据；对应轨迹与源码身份、限制见 B7 和根 `docs/KNOWN_ISSUES.md`。历史诊断原文与日志可从历史节点恢复。
