## 这版具体做了什么

- 父轨迹：`tabletop_pick_place_hybrid_OPTIMIZED_SDKALIGNED_REVIEW.json`（A 版），
  SHA-256 `e5fd11010815020dcc67deebfe774381b391e5462486eb67f8e5ee9150ec9c59`。
  只复用初始点到 `CLOSE_AT_PICK` 的前导，逐点保留；拿起后重新规划，不宣称整条原路线不变。
- 右臂以左臂物理夹持中心的位姿为参考，关于机器人中面对称，使用右臂模型求完整姿态 IK。
  关节取反只作为初值，不直接作为右臂输出。
- 两臂使用统一时间轴，每阶段一起到位，再执行开合或下一阶段。
  这验证了仿真中的双臂调度表达方式，**没有验证 SDK 可以并发下发或同步到达**。
- 夹爪代理及物体同时显示；夹持后物体刚性跟随整个末端姿态，释放后独立落向桌面。
  落下是显示假设，没有接触动力学、摩擦、夹持力或稳定落瓶仿真。
- 使用 `arm_profiles` 的臂映射、夹爪包络和限位；密化步长取父轨迹与共享步长上限的较严者。
  右臂只有标称限位和候选夹爪参数，没有假造实测限位。
- 抓取后抬高 150 mm，放置目标相对拾取点：左臂 `[+100,-40,+12] mm`，右臂镜像。
  这些是示意任务参数，不是 SDK 世界坐标。两臂始终留在各自半区。
- 放后抬高到拾取高度上方 200 mm，向后退 150 mm，再去 Home 上方 200 mm、固定 Home 姿态下降、
  最后对齐原固定关节 Home。新增这段是因为直接 MoveJ 回程会扫到已放瓶，不能只验终点。
- 新解统一保留共享的 5° 关节余量；原 A 前导未改，亦满足当前配置余量。

坐标是 **URDF_WORLD_SIM_ONLY**，不是 SDK 世界坐标。桌顶根据假定 200 mm 高瓶与抓取中心推算；
瓶径假定 70 mm，桌为 1.2×0.8 m，**本轮演示场景没有料框**。
未来若测试本场景，须将实际料框移出运动区域，或重新提供框位置纳入检查；
“不往框里放”不等于可以忽略仍留在路径里的框。桌的当前真实注册位置、右臂工具均未确认。
初始姿态来自父轨迹的历史读取点，不是现场当前状态；结束到 A 的固定 Home 及右臂对应 IK 姿态。

两臂独立做 IK 成功，不等于合在一起安全。厂商手部网格与实际夹爪有差异，但也不能直接忽略；
这版同时保留网格和保守夹爪盒检查，没有关闭腕部碰撞。
检测覆盖每个显示样本的全机器人、跨臂包络、持物/已放物和桌板；不是连续扫掠数学证明。
只排除机器人直接父子链接，其他腕部交叠照报。
本臂夹持接触与未持物碰撞分别列出，释放后的撤回也检查。

腕部网格在 J6/J7 合法网格抽样中仍全部交叠，不能通过换搬运路线消除。复杂完整 STL 的凸包近似
可能填平空洞，工具也未匹配实物；这既不能证明真机必撞，也不能证明真机安全。
接近、抓取及释放后刚向上退出时，完整手部/实心夹爪盒仍与本臂瓶子交叠；代理没有指间空隙，
不能把这些一律当成合法夹持接触。这些报告继续保留，整机资格为 REJECT。
真机前需可信开/闭夹爪几何、右臂实测限位/TCP、当前场景标定与 SDK 并发语义确认。
`real_motion_authorized=false` 和 `debian_execution_allowed=false` 不变，本轮没有真机入口。
