# 20260729 hybrid(关节转运)真机三连败记录

## 结论
`MODE="hybrid"` 暂停使用。主线回退到 `MODE="point"` + `TRANSFER_MODE="line"`
(全 armMoveWorlds 直线, 转运按单轴拆分)。

## 三次失败

| 运行 | 现象 | 性质 |
|---|---|---|
| 1 | 预检报 `TRANSFER_END` j4 余量 3.3° 通过, 正式执行前 `check_limits` 又拒 (`j4=-116.67` 超出收 5° 后的 `[-115,-5]`) | **代码缺陷**: 两处用了不同限位标准 |
| 2 | `armMoveJoints` 25s 未到位, 残差 23.720° | 待查 |
| 3 | `armMoveJoints` 25s 未到位, 残差 18.533° | 待查 |

两次超时都发生在**夹爪已闭合、物体在手**之后 —— 异常退出时夹爪仍是闭合的,
恢复现场前先确认物体和夹爪状态。

## 为什么还不能下结论

run3 的转运行程: j4 约 53°(由预检余量反解 PICK_ASCEND 位形得到), 25s 走了约
34°, 平均 1.37°/s。按这个速率还差约 14s。所以**看起来**像"走得慢没走完"而不是
"卡死"。但当时的 `wait_until_joints` 只打印一个总误差数字, 没有 move_state、
没有报警、没有误差随时间的变化, **无法排除中途停住**。这两种情况处置完全相反:

- 走得慢 → 加大 `timeout_s` 即可, hybrid 方案本身可用;
- 中途停住 → 加多久都没用, 要查内部软限位/保护/位形。

## 已做的修复

1. `preflight()` 现在对每个拐角的实测关节角直接跑 `ss.check_limits()`,
   用**最终生效的那套标准**判定 —— 让 run1 那类冲突在**夹爪闭合之前**就失败。
2. `wait_until_joints()` 补上滚动停滞检测 + 失败报告(逐关节误差 / 已走多少 /
   平均速率 / 预计还需多久 / move_state / alarms / 判读提示)。
3. 新增 `diag_joint_transfer.py`: **空爪**诊断脚本, 90s 超时 + 5Hz 全程采样,
   直接输出"慢还是停"的判读。要继续研究 hybrid 先跑它, 不要带物重复试。
