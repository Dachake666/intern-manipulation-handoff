# 审阅边界与旧记录修订

本节是本次交接的明确审阅意见，不是把旧记录静默改写成新事实。

## 1. “跑完”不等于“安全资格完成”

`SERVO_COMPLETED_RETURNED_HOME` 说明执行器报告流程完成。它不自动证明真实碰撞模型、持物/释放扫掠、夹爪已夹稳、连续跟随误差或绝对位置精度。原 9 月 9 日 ZIP 的 README 已声明场景/动力学资格不足；后续操作者监督 field trial 不能被悄悄写成通用部署 PASS。

日志中存在“关闭突变保护”的提示。保留为实际运行历史，不将它变成默认推荐。重新运行前必须由现场负责人确认有效保护、清场、独立急停和停止行为；本交接包不运行或解除任何保护。

## 2. GUI hash 重绑历史必须如实记录

现场先修改 candidate 的五个等待值，然后依次遇到 candidate allowlist、GUI candidate 绑定、GUI 文件自身 SHA 三层报错。此前对话指导更新脚本 allowlist，并直接把原 GUI review 的轨迹 hash 替换成新 hash。

**只替换 hash 并保留 PASS 不等于完成新 GUI 回放。**现有记录未建立一次独立的新 GUI/时序审核。此操作不能当作以后处理 mismatch 的通用方法。需要保存旧审阅的真实适用范围，并在新版本/时序变更后生成真实审核结果；缺资格时保留缺口。

因此本包只提供历史新 GUI SHA，不生成新 GUI PASS，不提供重绑 allowlist 的自动脚本。

## 3. Mac 与 field 的 pacer 不同

原 ZIP 的 `StrictPacer.before_send()` 在 `late > 2 * period` 时抛异常停止。现场报告则写 `REALIGN_AND_CONTINUE_NEVER_CATCH_UP` 并记录 `realigns`。同名 `servo_common.py` 不能假定相同。先收当前源码，阅读差异、保留两套语义，不因“方便复现”自动把 stop 改成 continue。

`realigns=0` 不是全帧按期的证明；这次仍有 21 次调用 >20 ms，最大 55.31 ms。`late_ratio≈99%` 也不能解释成 99% 丢帧；要看具体定义、时钟、阈值和实际反馈。

## 4. 网络证据的强度

- 对话中的同时间 Pulse/ICMP 恢复是通信路径相关性的强证据，不足以完全排除主机调度或给某个 driver 定责。
- 简单 ifconfig down 后后来发现 STA 又 UP；这一事实证明“关闭没有持续保持”，不证明谁重启，也不回溯证明之前每一轮的 STA 状态。
- UCI 禁用前后这批改善强烈支持上游 STA/AP 并发相关配置为主要诱因。airtime、重传、驱动/扫描、后台负载等机制仍未分别证实。
- 25ms 的 `>20ms` 只是统一统计阈值，不是该模式自身 25ms 截止期违约数。
- 四轮样本不足以宣布永久无长尾、硬实时，或绝对判定 25ms 没价值。按用户要求保留全部三模式。

## 5. 轨迹数学与硬件响应

VAJ3 的 19.91 / 829.26 / 41463.06 是名义命令采样的速度/加速度/jerk 诊断，非真实反馈，也不是厂商额定能力证明。C² 表示位置、速度、加速度连续，不自动保证 jerk 在段间连续。0.0641° corridor 是关节空间偏离，不是笛卡尔净空或新的碰撞证明。

## 6. 历史网络操作不能漏记

旧回复只列 STA 和 Wi-Fi，漏掉了更早的 Ethernet profile 修改：manual 172.24.1.8/24 → DHCP，metric -1 → 50，后来获得 .244。完整恢复要区分“最近试验前”与“最初接线前”两种基线，见恢复文档。

旧 MD 提到 powersave=2，但原值和本次现场命令回执不完整；不能武断设回 0 并称恢复成功。不要把 EEE 查询当作已经修改 EEE。

## 7. 不再执行的做法

不删除 `.lock` 文件绕互斥，不把 kill -KILL 等同机器人停止，不丢弃失败日志，不复用已覆盖的固定日志名、不从单次 TX bitrate 判定链路故障、不把历史 SSH/网卡状态说成现场实时状态。
