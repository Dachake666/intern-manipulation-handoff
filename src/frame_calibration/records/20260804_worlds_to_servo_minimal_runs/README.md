# 20260804 armWorldsToServo 最小验证 —— 5 轮真机全过

**这是 `armWorldsToServo` 第一次在真机上真正跑起来。**
此前 CW 那条线虽然叫「末端透传」，实际走的是
`armTryWorlds` 逆解 → `armPluseToServo` 发关节角，`armWorldsToServo` 一次都没调用过。

## 结论（措辞按证据边界）

**已证明**：当前机器人、当前 anchor 邻域内，`armWorldsToServo` 可用，支持
**30~50mm 平移**、**10~20° W 轴旋转**、**25~50mm/s 指令速度**。

| 指标 | 5 轮最大值 | 门限 |
|---|---|---|
| 位置误差 | 0.48 mm | — |
| 姿态误差 | 0.17 ° | — |
| 实际关节 vs `armTryWorlds` 终点预测 | 0.96 ° | 5 ° |

**尚未证明**：

- 所有**中间帧**都选同一 IK 分支（只比对了每段终点）
- 不同 anchor / 带负载 / 复合旋转 / 完整抓放
- 日志里的 50mm/s 是「步长÷周期」的**指令速度**，当时脚本没有节拍统计，
  实际速度和迟到帧未测（已在新版脚本中补上）

## 线路定位

**局部笛卡尔精修工具，不是抓放主线。**

| 阶段 | 用哪条 | 理由 |
|---|---|---|
| 大范围转运、绕障 | `armPluseToServo`（pulse） | 路径提前规划，执行序列确定，成熟度最高 |
| 到达 pre-grasp | pulse | 可结合 RRT + 碰撞检查 |
| **最后 10~50mm 对准** | **`armWorldsToServo`** | 笛卡尔方向直观，适合视觉坐标修正 |
| **小角度姿态校正** | **`armWorldsToServo`** | 已验证 W 轴 10~20° 可用 |
| 长距离搬运 | pulse | 不承担在线 IK 分支风险 |
| **放置前局部对准** | **`armWorldsToServo`** | 可直接吃相机给的毫米级偏差 |

这个分工特别适合后续视觉接入——相机给的通常是「向左 8mm、向下 4mm、转 3°」
这类笛卡尔修正，直接交给 `armWorldsToServo` 比重新生成整条关节轨迹自然得多。

## 现场手改 vs 仓库版本（已修）

最强的 #3~#5 三轮来自现场手改常量，**当时仓库版本复现不出**，而且日志段名
写着「上升 30mm」实际走了 50mm。

新版脚本参数全部走命令行，段名由参数自动生成：

```bash
python3 test_worlds_servo_minimal.py --run \
    --z-mm 50 --y-mm 50 --w-deg 20 --step-mm 1.0 --speed 10
```

## 新版脚本相对当时的四项加强

1. **逐点逆解预检**（原来只检每段终点），且第一个点与**当前实际关节角**比对
   —— 这正是完整版 CW 栽的那个「起手 119mm 阶跃」
2. **硬性验收门限**：位置 ≤1mm / 姿态 ≤0.5° / 预测差 ≤2°，不达标直接中止
   （5 轮实测全部满足，故以此为基线）
3. **节拍不追赶补发**：落后超过 2 个周期就重新对齐，不让积压帧背靠背连发
4. **清理期间屏蔽第二次 Ctrl-C**，确保恢复保护走完
